Apps in Entra ID are typically assigned to groups. Adding someone to the group grants the app, and Entra's own provisioning carries it from there.

## Connect

**Settings → Integrations → Microsoft Entra ID.** Register an app with the **application** permission `GroupMember.ReadWrite.All` (grant admin consent) and a client secret, then enter the tenant ID, client ID and secret.

This is a write permission. [Directory sync](/identity/directory-sync#microsoft-entra-id) only needs `User.Read.All` and `GroupMember.Read.All`, so you may prefer a separate app registration for provisioning.

## Map access levels

Each access level maps to an **Entra group**, listed from your tenant.

| On grant | On removal |
|---|---|
| Added to the group | Removed from the group |

<Warning>
  Dynamic-membership groups can't be changed through Microsoft Graph, so they aren't offered. Mail-enabled security groups and distribution lists are managed in Exchange, not Graph: use assigned security groups or Microsoft 365 groups.
</Warning>

People are found by user principal name, then by mail. If someone has no account, the request goes to the fulfillers with that error. Someone already in the group counts as success.
